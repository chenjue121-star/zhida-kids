# A 阶段 UI 首轮确认稿

状态：待用户确认，不是已批准的实现依据。仅设计资产，未修改页面代码。

## 画板

1. `01-login-family-invitation.png`：登录、我的家庭、接受邀请。
2. `02-family-children-profile.png`：家庭管理、孩子列表、新建孩子档案。
3. `03-preferences-states.png`：穿搭偏好同一页面的上下段，以及关键状态示例。

生成方式：内置 Image Gen。视觉参考为用户提供的草木绿儿童穿搭稿；后两张附第一张生成稿保持统一。各移动端内容框按 390 × 844 逻辑尺寸设计，画板不是可运行页面。插画头像为泛化演示形象，不代表 AI 试穿或真实孩子照片。

## 设计基准

- 草木绿 #43884C；选中浅底 #EAF5E5；晴天黄 #FFD86B；辅助浅蓝 #EAF4FB。
- 白色主体，正文 #26382D，次级文字 #68766D。插画集中在欢迎、家庭身份和风格示例。
- 正文目标 16px，主要标题 24px，操作区至少 48px；分组依赖间距、分隔线，不将每个区块包装成浮动卡片。
- 不加入尚未实现的推荐、衣橱或 AI 试穿入口；孩子照片非必填，A 阶段不展示未实现的上传按钮。

## 确认时需一并核对

- 邀请页权限仅为说明，图中的右箭头应去除，不允许受邀者自行改角色。
- 状态示例中的“等待家人添加宝贝”和“添加宝贝”属于不同权限版本；仅查看成员不能出现添加按钮。
- 偏好画板左下方是个人标签页的状态示意，不在实际页面重复放第二份保存区。
- 家庭共同偏好是共同维护的显式风格列表，不是算法汇总所有家人的喜好。
- 表单未知值为空；新增资料和编辑资料共用路由，但编辑版保留测量记录与归档入口。编辑、成员管理弹层等细节需在视觉方向确认后补充确认，不以此概念稿宣称全部交互已验收。
- 勾选协议属于设计建议；正式接入前必须具备真实协议内容与入口，不能放空链接。
- 图片中文字、插画和控件均为首轮视觉稿，最终布局须经过原生窄屏和长文本验证。

用户确认页面与交互后才可编写 UI 实现代码。
