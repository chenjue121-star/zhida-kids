状态：设计已确认，A 阶段对应实现位于 `codex/phase-a` 工作区。图片仍是评审稿，以实际小程序界面和测试结果为准。
图像使用内置 Image Gen 生成，以已展示的草木绿、晴天黄、浅蓝儿童服饰视觉为参考。图中人物为泛化插画，不代表上传照片或 AI 试穿功能。

## 首次必经与按需入口

首次普通进入：设置一个孩子（仅年龄必填，昵称默认“宝贝”，风格可选）→ 点击开始搭配 → 首次云端保存时登录 → 自动保存孩子并建立默认个人数据空间 → 首页。

登录不是新的资料填写步骤。不请求手机号、头像或定位。取消或失败保留草稿，不宣称云端保存成功；登录成功自动继续原保存动作，不让家长重填。未登录暂存仅是草稿，不得用访客路径绕过后端鉴权。

邀请进入：预览邀请 → 必要时登录并保留邀请上下文 → 明确接受 → 查看对方家庭已有孩子。不要强制受邀者先新建自己的孩子，也不自动加入。

再次进入：恢复有效账号和上次选中的孩子 → 首页。账号失效再登录，权限变化时重新核对家庭，而不是展示残留私有资料。

家庭管理、完整资料、测量、第二个孩子均为后续按需操作。天气请求只在需要天气的首页发生，拒绝定位可选城市；天气失败不显示假温度，不阻塞使用。

## 补充交互约束

- 年龄按“填写时的岁月数 + 记录日期”保存，不伪造精确生日；后续填写生日后据此计算年龄，不保留两套互相冲突的可编辑年龄。
- A3 画稿中的年龄控件仅适用于尚无生日的状态。填写生日后年龄改为只读计算值；完整字段冲突规则需在实现方案落实。
- 首次默认个人空间的创建与孩子保存需要幂等、事务保证；对用户隐藏家庭建档，不是移除后端权限边界。
- 默认昵称多个孩子重名时，切换项显示年龄辅助区分，身份仍以稳定 ID 识别。
- 归档当前孩子后选择剩余有效孩子；全归档则显示添加入口。viewer 无添加／归档按钮。
- 新增测量成功后读取权威最新记录，较旧日期不得变成“最近测量”。
- 退出或被移除后清理对应家庭显示与缓存，保留其他家庭和账号；没有可访问家庭时显示空状态，不无限跳转。
- 设置页的“家庭备用城市”为可选提案，不替代当前用户定位。未设城市不阻止家庭建立；不因首次使用收集家庭地址。
- 邀请重复打开：已经加入则显示“已加入”及查看入口；过期／他人已使用显示不可用，不重复创建成员。
- 保存中禁用连点并保持按钮尺寸；失败可重试且使用同一逻辑操作的幂等键。网络错误保留填写，不用退出登录解决。
- 照片可选且 A 阶段暂不开放上传；通用头像不可包装成真实宝宝形象。

## 画稿校准说明

画板为布局与风格稿，不是可运行原型。部分画面将成功态、移除确认、归档确认并排示意，实际仅在相应操作后出现。

1. A2 “已有多个家庭成员时使用”应改为“加入多个家庭时显示”；家庭数量与成员数量不是一回事。
2. A8 radio 每一行只保留一个选择控件；画面里重复的选中标记不照搬实现。
3. A1 取消登录仅保证保留草稿，不承诺未登录即可保存云端；协议内容和正式入口须单独准备，不能落空链接。
4. 状态图说明文字属于审核注释，不直接放入小程序。只读状态不出现可提交按钮；空状态的添加按钮只给有权限的成员。
5. 偏好参考稿“全家人的偏好”指共同维护的显式配置，不代表自动学习或自动合并各人喜好。
6. 所有示例年龄、测量和城市只是演示，不能当成新用户默认值；年龄初始应未选择，用户完成选择后才能保存。

## 与原实现的差异

新实现允许按岁月数建档，在首次保存时以事务建立默认个人家庭和孩子；登录失败会保留未提交草稿。家庭备用城市可空，首页仅在需要时定位，并可手动选择城市。天气服务未配置或不可用时不显示模拟数据。

衣物识别、穿搭生成、替换衣物不计入本包的 A 阶段完成项；之前的相关画板是后续核心体验预览。三 Tab 导航亦是后续整合提案，不因本包自动更改原阶段范围。

剩余验收：在原生模拟器与真机检查视觉和定位授权流程，配置专属天气 API Host 后验证实况，并用两个真实微信账号验证邀请协作。
