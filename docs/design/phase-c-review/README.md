## 已确认的 C 产品要求

1. 用家庭已有的真实衣物，优先可穿、合身和舒适，再考虑整套协调、偏好和适度变化。衣橱不足时说明缺项，不虚构单品。
2. 首页依次呈现孩子、今天／明天及实际日期、对应地点天气、场景、主搭配、简短理由和下一步。真实单品照片用于找到实物，不用 AI 试穿图替代。
3. 首次场景为日常，此后沿用每个孩子最近场景。记住上次孩子与日期模式；跨日重新解释日期，昨日已选方案不能被标成今日。
4. 家庭统一偏好为默认，可用指定成员或当前使用者偏好。不同依据的建议与缓存隔离；舒适、合身、可用状态始终共享。
5. 换整套、换单品、固定单品，以及从衣橱指定一件发起搭配。换一套保留固定项；没有其他合理组合时明确说明。
6. “选这套”建立家庭共享已选方案；重复点击只产生同一条。它不表示已经实际穿过。
7. “修改这套”更新原方案；“新增一套”保留原方案并创建另一条，同孩子同日可有多套。
8. 天气、衣橱、偏好、后台推荐或账号切换不静默改写已选方案。有影响时提示家长决定。
9. 备用按需展开，可为整套或兼容的局部衣物，不要求换衣时记录，也不追问补记。
10. 同一件家庭共用实物按目标日提示其他孩子占用，不能无提示地分配给两位孩子。
11. 天气未知明确告知；推荐供应商失败有同规则兜底。加载与失败保留已有方案，无法合理搭配时给可继续的路径。
12. 按账号、家庭、孩子、目标日期和推荐依据处理上下文；切换不丢调整、固定和已选状态，迟到响应不能覆盖新上下文。
13. 仅查看成员不可选定、修改或新增方案；可见的建议范围、是否可请求新建议，以及家庭授权与版本冲突在后续异常组完整审阅。

导航继续采用已确认的“搭配／衣橱／我的”，日历入口在 D 再确认。C 建立后续日历使用的方案数据，不提前宣称日历完成。

## 第一组：每日推荐与选定（已确认）

用户回复“可以”，据此确认已展示的第一组产品与 UI，继续第二组。确认范围包括直接给一套、按需调整条件、今天／明天和孩子分别保留上下文、已选不静默改写，以及修改／新增的明确入口；后续组细节仍逐组审阅。

本组先确认首页信息顺序与主流程，再讨论单品调整和复杂异常。

| 画板 | 讨论内容 |
| --- | --- |
| 01 今日建议 | 当前孩子、具体日期、目标日天气、场景、推荐依据；真实单品、简短理由；换一套与选这套；备用按需展开 |
| 02 准备明天 | 独立日期和天气；明天的场景、建议与选择；不覆盖今天已选方案 |
| 03 已选方案 | 选择人和家庭共享状态；保留原衣物；明确修改原方案与新增另一套；天气变化只提示影响 |
| 04 切换宝贝 | 切换列表显示各孩子的已选／待选摘要；往返后保留其日期、固定、调整与选择状态 |

推荐采用“进入就给一套，条件按需调整”。相比之下，多套并列让家长多做一次比较；先填完整条件再推荐则增加每日重复输入。本组呈现推荐方案供审阅，不将另外两种方式混入实际首页。

### 本组确认内容

- 日期标签同时写“今天／明天”和实际月日；当天日期由家庭时区确定，日期切换读取该目标日天气。
- 首页场景与偏好依据作为轻量入口，默认不增加必填表单。场景按孩子记住最近选择；当前孩子当天和明天已有的草稿上下文分别保留。具体持久化和默认继承规则在后续完整规格中收敛。
- 未选时主操作为“换一套／选这套”；选定后显示“已选好 · 家人可查看”，操作变为“修改这套／新增一套”，不继续用同一建议的选定按钮。
- 已选态将家人选择信息与衣物内容一起呈现。“已选”与“已穿”保持分开；不给未发生的穿着或洗衣事实贴标签。
- 天气变化提示为“天气预报有变化，已选搭配已保留”。让家长查看影响后决定；查看影响本身不修改原方案。
- 切换列表展示简短状态，不把全部衣物缩略图塞进每个孩子的列表项。新增孩子和资料维护沿用 A 的入口，不在本组重复设计。

完整单品替换、方案编辑、多套列表、备用选定和占用确认在后续组展示。第一组涉及这些能力的入口，只作布局示意，不把未完成的交互宣称为真实保存。

## 第二组：替换与固定单品（已确认）

用户再次回复“可以”，据此确认第二组已展示的单品操作、候选确认、固定换套、临时排除与衣橱指定实物发起，继续第三组。确认包括明确解除固定、新候选不继承固定、衣橱指定件自动固定、原建议可恢复，以及失效／缺项时保留草稿并提示的本组提案。

目标：保留满意的衣物，只调整需要改变的部分；从衣橱指定实物后能够补齐其他衣物。本组围绕未选建议展开，不提前保存或改写家庭已选方案。

| 画板 | 讨论内容 |
| --- | --- |
| 05 单品操作 | 点击真实单品，查看原图、替换、固定／解除固定、本次不穿；固定与替换的冲突明确说明 |
| 06 替换单件 | 展示符合当前孩子条件的可替换候选；选中后明确确认，取消不应用；其余衣物保持 |
| 07 固定后换套 | 固定标记可见；换其他单品保留固定项；没有其他合理组合时保留当前建议并解释 |
| 08 衣橱指定一件 | 从衣物详情发起，保留孩子、日期、场景和偏好；指定件进入新建议，不复制实物，不覆盖原建议或自动选定 |

### 本组确认内容

- 采用“点单品 → 替换／固定”的显式入口。完整编辑页适合后续方案核对，日常单品调整不先要求填写整套；不以隐藏手势作为唯一入口。
- 固定限当前孩子、目标日期的这份建议草稿，不改变衣橱归属或生成永久锁定规则。解除固定由家长明确操作；被固定单品不能在换套或替换时被静默移走。
- 替换列表中的选择是暂存，点“换成这件”才应用；关闭／返回保持原单品。替换完仍是待选择的建议，不等同于已选或已穿。
- “本次不穿”只作用当前建议草稿；可以撤回，不修改共享可用状态，不作为审美反馈。待洗／找不到、穿小了分别遵守 B 的实物状态／孩子合身语义，完整原因处理在后续组细化。
- 从衣橱发起创建独立建议草稿，指定件明确固定；保留来源实物身份。返回原建议可恢复先前调整，不能直接覆盖家庭已选方案。
- 指定衣物不可用或不合身时说明原因，引导先核对衣橱；不得为了生成组合自动改为可穿或合身。未知合身／厚薄和共用占用的完整边界在异常与占用组确定。
- 无其他合理组合时保留当前搭配和固定项，让家长主动决定是否解除或增加衣物；不虚构候选，不用不合适的组合填充“换一套”。

第二组仅演示“小豆子 · 2026-10-03”这一上下文；跨孩子／日期的完整模拟已在第一组展示，本组不把固定状态串入第一组原型。图片与可穿／合身均为明确标注的设计样例。

## 第三组：备用与一天多套（已确认）

用户回复“下一步”，按已约定的逐组评审流程确认第三组并进入第四组。确认范围为已展示的可选备用、备用暂存／核对、附属方案与实物去重、稳定编号多套列表、修改／新增／放弃，以及家人刷新时保留草稿；异常的完整处理仍在第五组审阅。

目标：准备时可以一次核对主搭配和备用，也可以不准备备用；同一天新增搭配不覆盖已有方案。延续已确认的“已选”语义，不要求换衣时记录，不追问事后补记。

| 画板 | 讨论内容 |
| --- | --- |
| 09 准备备用 | 按需选择无备用、局部或整套；真实实物、兼容用途、同一双鞋沿用；暂存、确认与取消 |
| 10 选定前核对 | 明确孩子、实际日期、场景与依据，主搭配和已选备用；区别更新原方案与新增一套 |
| 11 今天已选 | 当日方案列表、选择人和备用摘要；按稳定身份查看／修改，备用不单独计为另一套 |
| 12 修改与新增 | 从指定方案复制草稿，修改更新同一条、新增创建新条；放弃与家人刷新不静默覆盖 |

### 本组确认内容

- 推荐准备时可一起选好主搭配与备用，同时支持选定后通过“修改这套”补充备用。相比只允许选定后补备用，打包准备少一次往返；不把备用变成必填步骤。
- 本组初始为小豆子 2026-10-03 已有第 1 套、当前准备新增第 2 套草稿，四画板共享演示数据。已有方案和新草稿始终明确区分，不自动导入第一、二组内存状态。
- 备用附属对应方案；局部备用可独立选上装或下装，并说明替换主搭配哪一件后与哪些衣物组合。备选推荐默认未选，未确认的备用不混入已选快照。
- 整套备用列明实际组成；本组衣橱只有一双示例运动鞋，因此明确沿用主搭配同一双鞋，不虚构另备一双。打包实物按身份去重。此组合示例的兼容性不是实际模型质量结论。
- 备用编辑暂存，确认后加入方案草稿；取消只放弃本次备用暂存。切换备用类型、调整主搭配后若影响原备用，需要明确说明并重新核对，不能静默保留失效备用。
- 选定前核对显示主搭配及实际确认的备用。“新增这套”创建另一条并保留原方案；“保存修改”更新指定原方案。取消核对保留当前草稿，确认后保存单品与依据快照；连续确认不重复新增。
- 列表按方案创建顺序稳定显示第 1／2 套，编号不代表实际穿着顺序。修改第 1 套保持身份和编号；备用摘要不增加方案数。当前查看通过方案身份保持，不依赖列表位置。
- 修改与新增均从已选快照复制独立草稿。放弃不会改变已选记录；带未确认改动离开或切换编辑目标时要明确处理，不静默丢失调整。新增从已有方案开始也必须明确取得新身份。
- 家人刷新只更新共享已选视图，保留当前查看方案及本人未保存草稿；同一方案已被家人更新时提示先核对，不自动合并或覆盖。完整版本冲突、未知提交结果与权限变化在第五组审阅；共用占用在第四组审阅。

本组仍仅为本地产品与 UI 稿；不连接推荐、保存、推送或占用接口。

## 评审期间收敛的边界

以下是各组形成时的历史问题，现已由 [完整 C 规格](../../superpowers/specs/2026-10-03-zhida-phase-c-design.md) 收敛，不再作为重复确认请求。

- 第四组已确认：主搭配与选定备用按实际目标日期提示跨孩子占用；同孩多套可以延续使用。分时需双方非重叠计划和具体理由，来源变化重新核对，保存成功才更新目标方案安排。
- 第三组已确认：同孩同日按创建顺序展示方案、按稳定身份查看；备用附属对应方案，准备时一起选择或以后通过修改补充。
- 第三组已确认：调整先形成草稿，明确修改／新增和继续／放弃；新增取得新身份，原方案保留。实现时还需落实跨页与持久化恢复。
- 单品换洗／找不到／穿小了与“本次不穿”的范围，如何避免临时原因形成审美标签。
- 局部备用的实时兼容校验、未知单品条件以及换洗原因的完整异常边界仍在后续组收敛；第三组已确认主件变化时明确移除草稿备用并重新核对。
- 天气变化影响的展示、相同天气不反复重算和目标日预报缺失的降级文案。
- 只读成员可以查看的共享内容与建议范围，以及成员降权后的在途结果。
- 选定结果未知时查询原操作；查不到不能当作明确失败后重交。复用 B 已验证的操作身份与恢复模式，需在 C 契约中落实。
