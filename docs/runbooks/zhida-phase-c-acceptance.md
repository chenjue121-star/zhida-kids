## 实现范围

- 搭配首页、调整页、选定前核对页，以及从衣物详情发起独立草稿的入口。
- 家庭时区的今天／明天实际日期、对应日预报、场景和家庭／当前成员／指定成员偏好依据。
- 真实衣物的可用、合身、舒适和组合规则；模型只排序已校验组合，异常回退基础规则，默认模型关闭。
- 固定、本次不穿、同类替换、无／局部／整套备用；候选与备用暂存、明确确认和取消。
- 同日多套、修改保持编号并增加版本、不可变已选快照、主备计划占用、按实物打包去重。
- 全部具体占用来源、非重叠分时安排与原因、来源身份／版本／用途变化后的重新核对。
- 衣物最新资料先展示、确认后才更新草稿；保存仍逐件核对版本、完整组合、备用和共用资格。
- 原操作保存、原回执查询、明确未执行围栏、响应丢失恢复、权限变化和迟到响应隔离；原成功不会覆盖家人后来更新的版本。

## 本地原生验收顺序

按 [本地运行说明](zhida-v2-local.md) 迁移 V2 开发库到 `0004_daily_outfits` 并启动 API，使用 `miniprogram-v2` 微信项目。保留现有 `.env.v2`，不要覆盖密钥。

1. 两个孩子分别准备真实、合身衣物，含手填无图、原图、未知合身、待洗、移出、共用实物；核对窄屏和长名称。
2. 分别进入今天／明天、切孩子及偏好依据，检查每份草稿自身场景、日期和来源；跨午夜后仍保留旧实际日期草稿。
3. 验证固定／解除／本次不穿、逐件替换、候选检查时再次选择、取消；从衣物发起后重开并返回原建议。
4. 验证局部／整套备用、取消、主搭配变更后重新核对、同件主备去重和不同实物同图计数。
5. 选定、明确新增、修改原编号、第二账号查看与竞争修改；共用按全部来源填写非重叠时段，来源变化后重新确认。
6. 保存响应丢失、重开、仅查询原操作、成功后的家人最新版本另行提示；原稿冻结、其他独立稿可准备但再次保存需等待。
7. 推荐／原图／候选在途切孩子、切家庭、降权或移出成员；旧结果不可覆盖新上下文，家庭撤权只清对应家庭。
