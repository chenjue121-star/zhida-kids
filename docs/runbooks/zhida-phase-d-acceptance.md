## 已实现

- 日历按已选方案读取，同日多套、按孩子和月份查看、显示撤销历史；详情保留选定时的衣物、备用、天气、偏好依据和操作人。
- 修改沿用 C 的版本核对；撤销追加版本并释放占用，响应丢失时只查询原操作，核实未执行会阻止迟到提交。撤销不删除原方案。
- 回看复用只准备新草稿，重新核对当前衣物、合身、可用状态、目标日期天气和共用冲突；资料变化需明确确认。前端给来源宝贝重新准备；后端也验证跨孩子目标归属。最终选定仍经过 C review/save。
- 原始反馈保留操作者、孩子、方案版本、来源依据和原因，重复提交同一事件不重复学习。家庭依据归家庭；成员依据归反馈操作者自己的个人偏好。
- 显式风格与推断分开展示，可回看证据、编辑明确风格、采纳正向推断或移除推断。负向推断不能采纳成明确喜欢；移除记录证据截止位置，旧事件不会立即重建。
- 至少三个不同方案的同向证据才展示推断；当前版本选择为弱正向，明确款式意见优先，待洗、找不到、偏小、舒适和跳过不形成审美标签。取消和修改后的旧弱选择退出，明确意见仍保留。
- 初版规则 `aesthetic-evidence-v1`：显式权重 1；推断强度除以 6、绝对值封顶 0.5，选择强度 0.25、明确意见强度 1。仅影响审美排序，不放宽舒适和合身过滤。未实现时间衰减，也未宣称这些数值已经验证个性化效果。
- 导航包含搭配、衣橱、日历、我的。新增 `0005_personalization_calendar`，启动仍依赖显式迁移和 readiness。

日历、反馈、日期经过均不能证明实际穿过；旧日记与旧穿着次数不会被转换成新版穿着事实。
