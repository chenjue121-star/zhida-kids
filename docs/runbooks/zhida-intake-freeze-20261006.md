# 待核对卡顿修复验收

日期：2026-10-06。工作区 `codex/phase-a`，本地开发环境。用户反馈点击进入待核对卡死后，完成页面加载修复与实际开发者工具验证。

## 原因与修改

原页面一次渲染全批高清原图，每张图片完成后重传整个列表。47 张照片对应 75 个候选节点；照片页的空上传队列还会触发额外刷新，离开页面后取图循环继续运行。

- 照片页与集中核对页每页显示 12 项，完整批次继续用于计数、确认和批量归属。
- 列表读取权限保护的 JPEG 缩略图，最长边 360px，小图不放大；完整原图仍通过原接口预览。
- 图片地址使用字段路径更新，刷新保留已加载地址。翻页、离开页面或权限改变后停止旧循环；空上传队列直接返回。
- 同安全上下文的进行中图片下载合并，缩略图与原图缓存分开；失败后可以重新请求。
- 勾选只修改当前页，保留其他页的选择。原图与缩略图使用同一权限校验，并在存储读取和缩放后再次核验。

只读 harness 的同一份 75 候选数据中，图片更新桥接 JSON 从约 4.22 MB 降为首屏约 1.41 KB；这项是模拟载荷比较，不是实际设备内存或耗时测量。47 张测试照片缩略图合计约 403 KiB。

- 新增 20 项前端分页与下载测试，覆盖过期响应、隐藏停止、刷新缓存、在途合并、失败重试、权限变化、跨页选择及全批确认。完整命令 `node --test miniprogram-v2/tests/*.test.js`：**364 passed**。
- 独立代码审查与隔离模拟复核上传队列、本机照片、跨页取消选择、批量归属及撤回，未发现阻断缺陷；JS 语法与 `git diff --check` 通过。
- 实际微信开发者工具打开批次 4：**47 张照片、75 件候选**，照片 4 页及集中核对 7 页逐页打开，滚动、完整原图预览、关闭预览及返回照片页正常，未再出现卡死。

## 使用与边界

重新编译已有小程序后，通过 **衣橱 → 继续 → 75 件候选的批次 → 查看候选** 进入。页面底部“下一页”继续核对，已选项会跨页保留。
