鞋面看得见，但孔洞纹理和多色拼接如何映射现有图案枚举尚未定义。这属于字典适用范围问题，不应直接写成“视觉不可观察”来排除评分。AI 草稿中的 null 只是待裁决占位，不能直接迁为正式标签。另有一个计数契约差异：审核规范将一双鞋作为一项，而当前生产提示词只写“一件可见实物对应一项”，尚未向模型明确配对。正式对测前需统一该规则；当前没有修改生产提示词。

审核者应独立查看原图填写自己的对象数、框和字段，再对照 AI 草稿检查是否漏件。完成争议裁决后，单独组装 `labels.reviewed.json` 并留存两份审核记录；不要仅把 AI 草稿中的 reviewed 改为 true。

| 场景 | 数量 | 覆盖要求 |

| 单件 | 60 | 平铺、悬挂、穿着、深浅色、复杂背景；上衣、裤、外套、裙、连体衣、鞋袜及配饰 |
| 多件 | 30 | 2–6 件；上衣＋裤、外套＋内搭、同色、同款多色、遮挡、两件套、购物拼图 |

同一照片复制、同一实物轻微改角度、图片增强，都不增加独立场景数。多个家庭、不同实物和拍摄环境有助于观察泛化。无需为了识别服装收集儿童正脸或其他身份信息。

先以这批诊断集排除明显不合适的模型，再扩展至 300–500 个审核场景，另保留盲测。稀有衣物和困难图单列结果，不只追求总体平均。

## 审核规范

1. 明确照片里应识别的实际管理单位：两件套拆成上衣和裤子，可另记套装关系；连体衣／包屁衣／睡袋为一件；鞋、袜、手套按一双／一对管理。购物图上的每款可作识别对象，但是否拥有由家长确认。
2. 以 EXIF 转正后的图为基准，框住各物品可见区域。框为 `[左,上,右,下]`，像素坐标分别除以图片宽、高得到 0–1 数值。两件独立物品分别有稳定对象 ID。
3. 两人独立核对类别、颜色、图案及对象对应，有分歧时裁决。`reviewed=true` 表示已经完成这一步，不表示“AI 填完了”。
4. 清楚可见的字段才放入 `observable`。厚薄通常无法从正面确认，此时 `thickness=null` 并从 observable 中排除。不要把隐藏内里或材质作为视觉模型必须猜对的答案。
5. 明确无衣物负例使用 `objects=[]`。尚未标注使用 `objects=null, reviewed=false`；两者不能互换。遮挡严重但仍可识别衣物时保留对象及可观察字段，不能为提高分数删除困难对象。
6. 使用匿名 `group_id` 将相关家庭／实物／拍摄会话放在同一集合。优先整家庭分组；相同实物的不同角度与衍生图不能跨 development/calibration/test。
7. 标签审核后保留原文件与 SHA256。换照片、裁剪或重新压缩需要重新核对标签；工具会拒绝旧标签对应的新内容。

## 标签示例

下面只说明格式，不是现有图片的实测真值。`sha256` 必须取审计生成的真实值。

```json
{
  "schema_version": 1,
  "entries": [
    {
      "image": "photo001.jpg",
      "sha256": "从该照片审计条目复制的SHA256",
      "group_id": "family001",
      "split": "development",
      "scene": "single_flat",
      "reviewed": true,
      "objects": [
        {
          "id": "garment001",
          "bbox": [0.1, 0.1, 0.9, 0.9],
          "category": "top",
          "colors": ["white"],
          "pattern": "solid",
          "thickness": null,
          "observable": ["category", "colors", "pattern"]
        }
      ]
    }
  ]
}
```

类别：`top/bottom/outerwear/dress/onesie/shoes/accessory`。颜色：`black/white/gray/red/orange/yellow/green/blue/purple/pink/brown/beige/multicolor`。图案：`solid/stripe/plaid/print/dots`。厚薄在可观察时用 `thin/medium/thick`。

正式标签不能用 unknown 表示可观察真值；确实无法观察的字段为空并排除，未完成审核留在草稿。同内容照片只保留一个正式条目，相关实物即使内容不同仍须同组。

## 对测与选择

命令和配置见 [新版评测 README](../../backend/eval/recognition_v2/README.md)。默认离线；真实运行需要审核清单、账号环境变量以及显式调用上限。先用 development 筛选；calibration 用于决定策略；test 不用于改提示词或挑阈值。

优先检查漏件、重复、字段串件、整件联合正确与未知行为，再比较实际延迟和 usage。模型原始建议与家长确认后的数据质量分别报告。公开通用视觉分数不能代替这份儿童衣物结果。

当前评分器按完整 `colors` 集合是否相同计分，报告颜色集合正确率；它没有独立的主色指标。可讨论的初始目标为单件类别／颜色集合各 ≥95%，可见关键字段联合 ≥90%，多件 precision ≥95%、recall ≥90%；这些是工程筛选起点，尚未达成或被验证，也不代表困难子组有相同质量保障。若另测主色，需先定义主色提取规则并设计独立指标。

先选择一个主模型，再验证“低成本首识别＋疑难复核”是否有净收益。复核触发不能只靠模型自评分；照片中没有视觉证据的厚薄仍保留未知。
