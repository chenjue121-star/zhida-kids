# Lite 衣物资料填充

用户选择 Seed 2.1 Lite 原识别方案并要求继续填充和开发。本轮沿用已经实现、确认的 B 阶段上传、持久任务、核对与显式入库流程。

## 实施范围

1. 识别默认采用 ARK `doubao-seed-2-1-lite-260915`，使用原生产提示词和现有 Chat API，保留 Qwen 显式配置能力。颜色角色实验不进入生产。搭配排序配置继续保持原值，本轮是衣物资料填充。
2. 本机配置仅补充识别供应商、模型、ARK 地址及既有密钥，不覆盖数据库、微信和天气配置。API 与独立 worker 同配置运行。现有队列按已授权的 Lite 填写功能处理，保留不确定请求不重复调用的规则。
3. 提供仅开发环境使用的确认库存导入工具。以已确认的 47 张原图、75 件主商品标签建立一个独立待核对批次，不重复调用模型。不自动裁剪近似 bbox、不确认实际拥有、不创建 Clothing。保留类别缺失、图案缺失、全部厚薄未知；本次草稿明确 fit=unknown、selected=false。普通拍照/相册默认合身可穿行为保持。
4. 导入必须绑定具体录入者、家庭、孩子，沿用当前权限核验、家庭锁与域服务；本机目前只有家庭 1、录入者 1 和有效孩子 1。原图私有存储、元信息清理、哈希核验与同家庭媒体去重沿用 B。确认清单与库存、来源图片哈希在任何写入前校验。
5. 重复导入复用稳定批次、照片项、候选，保留人工修改、选择、放弃和已确认状态。全部导入在一个事务中完成；中断后可复用已写私有媒体再执行，不重复造实物。不伪造识别 attempt 或模型来源。

## 核对与验收

原图核对、多件候选、批量归属/合身、部分确认与操作重放使用已有页面。合身未知不会进入可穿推荐，需要家长明确核对。测试集标签的总体确认不作为拥有、合身或天气资料的证据。

离线测试验证 Lite 原请求契约、未配置手填、Qwen 保留，以及导入幂等、人工编辑保留、未知信息、权限与来源校验。真实本地验证 API readiness、worker 可用、导入数量与零自动入库，并检查实际小程序草稿。记录真实外部调用数量和本轮限制。
