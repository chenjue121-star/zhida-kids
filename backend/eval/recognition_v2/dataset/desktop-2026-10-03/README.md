## 标注范围与分组

这批实际为商品页面截图，有标题、商品文字、色款缩略图、轮播标记，少数主图还有模特配搭。它适合诊断商品截图录入；网页文字可能帮助模型回答，结果不能单独代表家庭实拍识别能力。

AI 草稿仅标主商品图片区的对象。可见上衣、下装、连体衣或配饰按独立管理单位拆件，所以 47 张截图提出 75 个对象建议；这个数仍待人工确认。页面缩略图、悬浮图和模特身上非主体衣物放入 `secondary_visuals`，没有把它们标成负例，也没有悄悄删去原图。

当前生产提示词和评分器没有“只识别商品主图、忽略色款缩略图”的契约。正式评分前需要冻结截图对象范围并审核对应真值。若测完整原图端到端识别，应将所有应识别对象纳入；若另设主图区域实验，需要独立定义输入与标签，不能把两种结果混为一个准确率。本轮只存 `hero_region_hint` 供核对，没有生成裁图或修改生产提示词。

类别建议为上衣 21、下装 25、外套 7、连衣裙 13、连体衣 5、配饰 1、待裁决 3；没有鞋类和明确无衣物负例。部分外搭、背带／裙裤结构、麻花针织、微小徽标、白／米或低饱和颜色需要统一口径。厚薄全部保持不可由截图确认；实际合身、状态、材质和拥有情况不由图片推断。

这批统一使用 `split=development` 和一个保守来源组 `desktop-family-20261003`。同款不同色、可能同商品的放大图仍需核实；不同文件内容不等于不同实物。这不是对 47 个独立家庭的盲测，也不自动删除相似款。疑似关联如 c021–c025、c030/c031、c038/c039、c040/c041 已记在逐图草稿中。

## 审核与后续对测

先独立核对原图，再对照图册补漏、修框、裁决类别及颜色／图案；两份审核意见有分歧时保留裁决。审核后的照片另存 `labels.reviewed.json`，其余继续留在草稿。不要仅修改 AI 文件中的 reviewed 标志；完整规范见 [采集审核说明](../../../../../docs/runbooks/recognition-evaluation.md)。

从 worktree 的 `backend/` 执行正式清单验证：

```sh
.venv/bin/python -c "from eval.recognition_v2.dataset import load_manifest; print(len(load_manifest('eval/recognition_v2/dataset/desktop-2026-10-03/labels.reviewed.json', 'eval/recognition_v2/dataset/desktop-2026-10-03/images')), 'reviewed samples')"
```

当前两份草稿均会被验证器拒绝，避免生成未经人工审核的准确率。审核清单准备好后，可用相同图片与生产链路比较已有三个候选配置。若 47 图全部审核、每模型一次，初次需要最多 141 个请求；这是调用次数，不是费用预算。本轮没有开启这一步。模型配置、离线重放与调用限制见 [评测工具说明](../../README.md)。
