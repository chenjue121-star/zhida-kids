# 智搭 — 衣服录入识别与搭配推荐 技术方案

> 状态: V2 (含补充方案整合)
> 日期: 2026-06-11
> 负责人: 扣子（Agent）
> 置信度: medium

## 1. 方案摘要

- **推荐架构**：本地优先 + 规则引擎过滤 + LLM 排序解释的混合架构
- **关键决策**：
  1. 衣物识别：iOS Vision 框架本地初筛 → 云端多模态 API 兜底，不做自训练 CoreML 模型
  2. 搭配推荐：本地 12 条硬规则过滤候选集 → 服务端 LLM 排序 + 生成解释
  3. 推荐缓存：KV 缓存当天推荐结果，每用户每天最多 1 次 LLM 调用
  4. 图片管线：三档尺寸（thumb/preview/origin）+ R2 存储 + CDN 分发
- **预期收益**：MVP 阶段实现完整"拍照录入 → AI 识别 → 每日推荐 → 采纳记录"闭环
- **最大风险**：衣物识别准确率不足导致用户手动修正成本高；LLM 推荐成本随用户量线性增长
- **评审阻塞项**：无（识别 API 选型已确认阿里云，要求覆盖 9 大类型+子类型并包含颜色识别）

## 2. 背景与目标

| 项 | 内容 |
| --- | --- |
| 业务背景 | 智搭是 0-6 岁儿童智能穿搭 iOS App，核心闭环是"录入衣物 → AI 推荐穿搭 → 采纳记录"。录入和推荐是产品最有价值的两个模块 |
| 技术目标 | 1) 衣物识别准确率 > 80%（类型+颜色），用户确认即可入库；2) 推荐生成 < 3s（含缓存命中）；3) 每用户每天 LLM 成本 < ¥0.05；4) 离线可用：规则引擎 + 本地数据不依赖网络 |
| 成功标准 | 新用户首件衣物录入率 > 70%；推荐采纳率 > 30%；推荐生成成功率 > 95% |

## 6. 方案选型与决策

### 决策1：衣物识别方案

| 决策点 | 推荐方案 | 放弃方案 | 选择理由 | 反转条件 | 置信度 |
| --- | --- | --- | --- | --- | --- |
| 衣物识别 | iOS Vision 本地初筛 + 云端多模态 API 兜底 | CoreML 自训练模型 | MVP 阶段无标注数据，Vision 零成本可用；云端 API 准确率更高但依赖网络 | 积累 5000+ 标注样本后可训练 CoreML 替代 | medium |
| 云端识别 API | 阿里云图像识别 | 腾讯云 / Google Vision | 阿里云服饰类目 200+，覆盖 PRD 9 大类型+子类型，支持颜色识别输出，国内延迟低 | 阿里云实测类型+颜色准确率 < 70% 时换腾讯云 | high |

### 决策2：搭配推荐架构

| 决策点 | 推荐方案 | 放弃方案 | 选择理由 | 反转条件 | 置信度 |
| --- | --- | --- | --- | --- | --- |
| 推荐架构 | 本地规则过滤 + 服务端 LLM 排序 | 纯 LLM 推荐 | 纯 LLM 会出现幻觉（推荐不存在的衣物、厚度不匹配）；规则引擎离线可用 | 规则引擎维护成本 > LLM 直接约束成本时 | high |

### Failure View

| 故障 | 降级路径 | 恢复 |
| --- | --- | --- |

| 网络完全不可用 | 规则引擎 + 本地数据完整可用，推荐无搭配理由 | 网络恢复后后台同步 |

## 8. 关键模块设计

### 模块1：衣物识别引擎（RecognitionEngine）

| 项 | 内容 |
| --- | --- |
| 职责 | 接收 UIImage，返回 ClothingAttributes（类型/子类型/主色/花纹/季节/厚度） |
| 非职责 | 不负责图片存储、表单展示、数据持久化 |
| 接口 | `func recognize(image: UIImage) async -> RecognitionResult` |

**数据模型**：

```swift
struct ClothingAttributes: Codable {
    var type: ClothingType        // top/pants/skirt/jacket/shoes/hat/accessory/set/inner
    var subType: String           // T恤/衬衫/卫衣/毛衣...
    var mainColor: ColorName      // red/orange/yellow/green/blue/purple/pink/white/gray/black/khaki/cream
    var pattern: Pattern          // solid/stripe/plaid/print/cartoon
    var suggestedSeasons: [Season] // spring/summer/autumn/winter/allSeason
    var suggestedThickness: Thickness // thin/regular/thick/fleece
    var confidence: Double        // 0.0-1.0 总体置信度
}

enum RecognitionResult {
    case success(ClothingAttributes)
    case partial(ClothingAttributes, failedFields: [String])
    case failure(Error)
}
```

**识别管线**：

```
输入 UIImage
    │
    ▼
Step 1: 预处理
  - 压缩至最大 2048px（保持比例）
  - JPEG 80% 质量
  - 生成 preview_600 尺寸用于云端识别
    │
    ▼

func extractDominantColor(from image: UIImage) -> String {
    guard let ciImage = CIImage(image: image) else { return "其他" }
    
    let filter = CIFilter(name: "CIAreaAverage")!
    filter.setValue(ciImage, forKey: kCIInputImageKey)
    filter.setValue(CIVector(cgRect: ciImage.extent), forKey: kCIInputExtentKey)
    
    guard let outputImage = filter.outputImage,
          let bitmap = renderBitmap(outputImage) else { return "其他" }
    
    let r = Double(bitmap[0]) / 255.0
    let g = Double(bitmap[1]) / 255.0
    let b = Double(bitmap[2]) / 255.0
    
    // RGB → HSL → 颜色桶映射
    let (h, s, l) = rgbToHsl(r: r, g: g, b: b)
    return mapToColorName(h: h, s: s, l: l)
}

func mapToColorName(h: Double, s: Double, l: Double) -> String {
    // 低饱和度 → 灰白黑系
    if s < 0.15 {
        if l > 0.85 { return "白" }
        if l > 0.65 { return "浅灰" }
        if l > 0.35 { return "灰" }
        return "黑"
    }
    // 高饱和度 → 按色相分区
    switch h {
    case 0..<15, 345..<360: return l > 0.7 ? "粉" : "红"
    case 15..<45: return "橙"
    case 45..<70: return l > 0.6 ? "浅黄" : "黄"
    case 70..<150: return l > 0.6 ? "浅绿" : "绿"
    case 150..<200: return "蓝绿"
    case 200..<260: return l > 0.5 ? "浅蓝" : "蓝"
    case 260..<290: return l > 0.6 ? "浅紫" : "紫"
    case 290..<345: return l > 0.6 ? "粉紫" : "紫红"
    default: return "其他"
    }
}

struct OutfitRule: Codable {
    let id: String
    let name: String
    let condition: RuleCondition
    let action: RuleAction
    let priority: Int          // 执行优先级，数字越小越先执行
    let enabled: Bool
}

enum RuleCondition: Codable {
    case temperatureRange(min: Double, max: Double)  // 温度区间
    case weatherType(String)                          // 天气类型
    case scene(String)                                // 场景
    case clothingField(field: String, operator: String, value: String)
    case and([RuleCondition])
    case or([RuleCondition])
}

enum RuleAction: Codable {
    case exclude                                      // 排除
    case deprioritize(weight: Double)                 // 降权
    case prioritize(weight: Double)                   // 提权
    case require                                      // 必须包含（如必须有上衣）
}

**规则执行顺序**：
1. 先执行所有 `type = "filter"` 规则（AND 关系，排除不合适的）
2. 剩余候选集执行 `type = "weight"` 规则，计算最终权重
3. 按权重降序排列，取前 N 件（N = min(候选集大小, 30)）送 LLM

**规则引擎执行流**：

```swift
class RuleEngine {
    private var rules: [OutfitRule] = []
    
    init() {
        // 先从 Bundle 加载 rules.json，失败则用硬编码默认规则
        if let url = Bundle.main.url(forResource: "rules", withExtension: "json"),
           let data = try? Data(contentsOf: url),
           let loaded = try? JSONDecoder().decode([OutfitRule].self, from: data) {
            rules = loaded.filter { $0.enabled }.sorted { $0.priority < $1.priority }
        } else {
            rules = Self.defaultRules
        }
    }
    
    func filter(clothings: [Clothing], weather: WeatherInfo, scene: String) -> [Clothing] {
        var candidates = clothings.filter { $0.status == "active" }
        var scores: [UUID: Double] = Dictionary(uniqueKeysWithValues: candidates.map { ($0.id, 1.0) })
        
        for rule in rules {
            let matched = candidates.filter { evaluate(rule.condition, clothing: $0, weather: weather, scene: scene) }
            switch rule.action {
            case .exclude:
                candidates.removeAll { matched.contains($0) }
            case .deprioritize(let weight):
                for item in matched { scores[item.id]! *= weight }
            case .prioritize(let weight):
                for item in matched { scores[item.id]! *= weight }
            case .require:
                break // 在组合阶段检查
            }
        }
        
        return candidates.sorted { scores[$0.id]! > scores[$1.id]! }
    }
}
```

   - 候选衣物描述只传必要字段（ID + 颜色 + 子类型 + 季节 + 厚度 + 风格），不传图片 URL 等无用字段，节省 token
   - 平均每次调用约 800-1200 input tokens，Haiku 成本约 ¥0.002/次

6. 调用 LLM
   - candidates.count < 10 → Claude Haiku (最便宜)
   - candidates.count 10-30 → Claude Haiku 初排 + Sonnet 解释
   - 超时 10s → 降级为规则引擎排序结果（无理由）

7. 解析结果
   - JSON 解析
   - 校验：推荐的衣物 ID 必须存在于 candidates 中
   - 校验失败 → 重新生成一次，仍失败 → 降级

8. 缓存写入
   - KV 写入，TTL 24h

9. 返回 [OutfitPreview]
```

**缓存 Key 计算细节**：

```swift
func cacheKey(childId: UUID, date: Date, weather: WeatherInfo, scene: String, clothings: [Clothing]) -> String {
    let weatherBucket = WeatherBucket.from(temperature: weather.temperature).rawValue
    let clothingFingerprint = clothings.map { "\($0.id):\($0.updatedAt.timeIntervalSince1970)" }
        .sorted().joined(separator: "|").md5
    let dateStr = date.format("yyyyMMdd")
    return "recommend:\(childId.uuidString):\(dateStr):\(weatherBucket):\(scene):\(clothingFingerprint)"
}

enum WeatherBucket: String {
    case freezing = "lt5"      // < 5°C
    case cold = "5to15"        // 5-15°C
    case cool = "15to20"       // 15-20°C
    case mild = "20to25"       // 20-25°C
    case warm = "25to30"       // 25-30°C
    case hot = "gt30"          // > 30°C
}
```

**缓存失效策略**：

```
缓存 Key = hash(childId + date + weatherBucket + scene + clothingFingerprint)

clothingFingerprint = MD5(所有"在穿"衣物的 [id + mainColor + type + status] 排序拼接)

主动失效触发条件：
  1. 用户新增衣物 → 重新计算 fingerprint，Key 自动变化（自然失效）
  2. 用户修改衣物属性（颜色/类型/状态）→ 同上
  3. 用户手动"刷新推荐"→ 直接清除当天 Key，强制重新生成
  4. 用户修改宝贝信息（身高/肤色）→ 清除该宝贝的所有推荐缓存

不需要主动失效：
  - 用户点了"就穿这套"→ 只记录日记，不影响缓存
  - 穿搭日记修改 → 不影响推荐缓存
```

```swift
actor PendingUploadQueue {
    private var queue: [PendingUpload] = []
    
    func enqueue(_ upload: PendingUpload) {
        queue.append(upload)
        trySaveQueue()
    }
    
    func processAll() async {
        for upload in queue {
            do {
                let urls = try await APIGateway.uploadAsset(image: upload.image, clothingId: upload.clothingId)
                // 更新 Clothing.photoURL
                upload.completion(urls)
                queue.removeAll { $0.id == upload.id }
            } catch {
                // 保留在队列，下次重试
            }
        }
        trySaveQueue()
    }
}
```
